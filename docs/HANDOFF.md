# Makeo 3D: מסמך המשך עבודה (Handoff)

מסמך לפתיחת סשן חדש. בתחילת הסשן כותבים ל-Claude:
"קרא את CLAUDE.md ואת docs/HANDOFF.md ותמשיך מאיפה שעצרנו".
את המסמך מעדכנים בסוף כל שלב משמעותי.

עודכן לאחרונה: 2026-10-26, אחרי build 52.

---

## 1. הפרויקט במשפט
אפליקציית אנדרואיד שהופכת תמונה למודל תלת־ממד, כולה על הטלפון (Galaxy S25 Ultra, שבב SM8750).
- ההרצה דרך ONNX Runtime, על ה-NPU (QNN HTP).
- יש שני מנועים:
  - **TripoSR**: מהיר, עם צבע.
  - **TripoSG**: צורה מדויקת, בלי צבע, ניסיוני.
- ה-package id עדיין `com.triposr.mobile`.

## 2. מצב נוכחי (build 52)

**TripoSR:** עובד. בהרצה מהירה כ-5 שניות, ובאיכות MAX כ-17 שניות.

**TripoSG:** עובד על ה-NPU. נבדק על ספל, והתוצאה הייתה "מושלמת" לפי המשתמש.
- חבילה `triposg-v4-int8`, בגודל 2.7 GB.
- מודל אחד לוקח 135 שניות ב-10 צעדים (build 50):
  - DENOISE: 64 שניות.
  - FIELD: 67 שניות.

**build 52, נבדק במכשיר על "מקמק":**
- FIELD ירד מ-43.5 ל-29.4 שניות, וכל המודל מ-126.6 ל-94.6 שניות.
- הצורה זהה לגמרי: אותו מספר משולשים, 374,112.
- שורת הזמנים בדוח: מתוך 29.4 השניות, ה-NPU לוקח 27.2. הכנת הנקודות לוקחת 1.1 שניות, וממנה מחכים רק 0.1.
  - לכן ההאצה הבאה צריכה לבוא מה-NPU עצמו (שלב ב', AKVS).
- הדמות הרצה מ-Subway Surfers יוצאת שבורה כבר בגרסה 50. זו תמונה קשה למודל, וזה לא באג של 52.
- **build 53:** תיקון של פס ההתקדמות ב-FIELD, שקפץ אחורה (100→72→100).

**רעיון להאצה נוספת:** ב-DENOISE נשארים טעונים רק 1–3 חלקים מתוך 7. שאר החלקים נטענים מחדש בכל צעד, ביחד כ-30 שניות.
- בבדיקת הטעינה נכנסו 6–7 חלקים.
- `KEEP_FREE_MB=2600` שמרני. הוא נקבע בתקופת חלקי ה-float, כש-LMK הרג את האפליקציה.
- אפשר לנסות להוריד אותו בזהירות.

**מה נבדק ומה התקבל:**
- **int8 (w8a16):** הצורה זהה ב-99.4–99.7% (IoU), ו-Chamfer יצא 0.27–0.32%. נכנס לאפליקציה.
- **הכוונה חכמה** (guidance interval 0.1–0.8): חוסכת כ-12% זמן, והצורה זהה ב-98–99%. מתג אופציונלי, כבוי כברירת מחדל.

## 3. התוכנית שעל השולחן
- **שלב א' (build 52):**
  - מה בוצע:
    - רצועה דקה: בבדיקה סינתטית ירד ב-33% מספר הנקודות שנבדקות, והצורה זהה;
    - צינור עיבוד מקביל;
    - מדידת זמנים.
  - צפי: FIELD יורד מ-67 לכ-35 שניות.
- **שלב ב':** Adaptive KV Selection, רעיון מהמאמר FlashVDM (arXiv 2503.16302).
  - הרעיון: לכל אריח (tile) של נקודות קרובות, לבחור רק את top-K מתוך 2048 טוקני ה-kv.
  - צריך לייצא `sg_vae_query` עם K קבוע (למשל 512), ומודל או חישוב לניקוד.
  - צפי: FIELD מהיר פי 2–3.
  - ⚠️ את הקוד של FlashVDM לא מעתיקים (רישיון Tencent עם הגבלות). כותבים בעצמנו מתוך המאמר.
- **אחר כך, לפי בקשת המשתמש:**
  - צביעה ל-TripoSG;
  - גרסת Dev;
  - חנות Play (רשימה ב-`docs/PLAY_RELEASE.md`).

## 4. איך עובדים

**כללי עבודה:**
- ענף: `ccr-755aee2e-0wbwnj`. עובדים ודוחפים רק אליו. PR רק אם המשתמש מבקש.
- אין Gradle מקומי. CI בונה את ה-APK: "Build Makeo 3D Android APK" (`build-apk.yml`).
  - כל push בונה גרסה ויוצר release עם תג `apk-N`.

**אחרי כל build:**
1. לחכות שהקובץ `Makeo3D.apk` באמת קיים ב-release.
2. להעתיק אותו ל-makeo3d-public: `mirror-release.yml` עם `tag=apk-N`.
   - ⚠️ להעתיק רק אחרי שהקובץ קיים. אם מעתיקים מוקדם מדי, ההעתקה נכשלת, והמשתמש מקבל עדכון ישן דרך כפתור העדכון.
3. לשלוח למשתמש את הקישור, בעברית ובפשטות.

**בדיקות איכות בשרת** (`triposg-eval.yml`):
- רצות כשמשנים את קובץ ה-workflow, ובהודעת ה-commit כתוב התג:
  - `[eval:guidance]`
  - `[eval:int8]`
  - `[eval:field]`
- התוצאות נשמרות בענף `eval-results`, בקובץ `summary.md` ובתמונות PNG.
- הכלי: `convert/sg_eval.py`. הוא משווה מול הצינור הרגיל על ה-CPU, ומודד IoU ו-Chamfer.

⚠️ **לא לגעת** ב-`convert/export_triposg.py` או ב-`convert/sg_model.py` בלי כוונה. שינוי בהם מפעיל את `build-triposg.yml`, שהוא בנייה מלאה ויקרה של חבילת TripoSG.

## 6. לקחים טכניים (כדי לא לחזור על טעויות)

**הגבלות ה-NPU:**
- שגיאת QNN 1002 = אין מספיק זיכרון. חלקי DiT ב-batch 2 לא נטענים, אז עובדים ב-batch 1.
  - שני ענפי ה-guidance רצים אחד אחרי השני.
- כל חלק טעון לוקח גם RAM. אם טוענים יותר מדי, Android הורג את האפליקציה.
  - `SgEngine` שומר חלקים טעונים רק כשה-RAM מאפשר זאת (`KEEP_FREE_MB`, `MIN_FREE_MB`).

**הסימן של ה-occupancy:**
- הדקודר המיוצא חיובי מחוץ לחפץ, ולכן האפליקציה הופכת את הסימן.
- בלי ההיפוך יוצאת "קופסה" סביב החפץ (82% "בפנים").

**זיכרון Java (heap):**
- מעל כ-600 אלף משולשים נגמר ה-heap. לכן `MAX_TRIANGLES` מגביל את הרשת.
- בדיקת ההדפסה מפשטת את הרשת לפני שהיא רצה.

**int8:**
- ב-calibration של ORT יש באג: `CalibMaxIntermediateOutputs` זורק את הנתונים.
- הפתרון ב-`quantize_triposg.py`: איסוף לכל דגימה בנפרד.

**Coroutines:**
- יציאה ממסך מבטלת את העבודה שלו. `CrashLog.error` מתעלם מ-`CancellationException`.

**סדר הורדות:**
- `Pack.reuse` מאפשר לשמור קבצים מחבילה קודמת שהסתיימה ושגודלם זהה.

## 7. חזרה אחורה (גיבויים ב-git)
לכל build יש תג `apk-N`, שמצביע בדיוק על הקוד שנבנה בו.

אבני הדרך החשובות (בשם התג של ה-build):

| תג | מה יש בו |
|---|---|
| `apk-47` | TripoSG עובד ראשון (float, 417 שניות) |
| `apk-50` | חבילת int8 (135 שניות) |
| `apk-52` | שלב א' של בניית הצורה (רצועה דקה, צינור מקביל) |

**פקודות:**
- לראות את הקוד של build ישן:
  ```
  git fetch --tags && git checkout apk-50
  ```
- לבטל commit מסוים בלי למחוק היסטוריה:
  ```
  git revert <hash>
  ```
  אחר כך push, ונבנית גרסה חדשה עם הביטול.
- להחזיר את הענף כולו לנקודה ישנה, **רק באישור המשתמש**:
  ```
  git checkout -b restore-X apk-50
  ```
  ובודקים לפני שממשיכים.
- APK ישן להתקנה מיידית:
  `https://github.com/israel0548502744-blip/Makeo3D/releases/download/apk-N/Makeo3D.apk`

**כלל:** בכל אבן־דרך חשובה מוסיפים שורה לטבלה שלמעלה עם תג ה-build שלה. דחיפת תגים ישירה מהסשן חסומה, ולכן תגי `apk-N` (נוצרים ב-CI) משמשים כנקודות שמירה.
